# 2026-08-07 개발일지

## 클라운 이동: "끊김 없이" + "판정 박자랑 맞게"를 동시에 만족시키기까지

어제 붙인 `Stage1WaveRideVisuals`의 클라운 이동(`SongTime` 웨이포인트 기반, cueBeat에 정확히 도착)을 실제로 플레이해보니 "리듬 맞춰 가긴 하는데 뚝뚝 끊겨 보인다"는 피드백. 여러 번 왔다갔다하며 정리됨:

1. **1차 시도**: 이동 시간을 `clownMoveBeats(1) × BeatInterval`로 늘려서 매 콜마다 쉬지 않고 이동하게 함 → 바로 "판정이 안 맞는 것 같다"는 피드백. 원인은 `CallDirector.OnCallCue`가 실제 정박(cueBeat)보다 `hitWindow`만큼 **먼저** 뜨는데, 이동 시간을 1박 전체로 늘리면 도착 시점이 `cueTime + (1박 - hitWindow)`가 돼서 판정 창(`cueTime ± hitWindow`)을 한참 지나 도착함. 시각적 신호가 실제 판정 타이밍보다 계속 늦어지는 문제.
2. **2차 시도**: `SongTime`을 직접 폴링해서 각 콜의 실제 cueBeat(초 단위)에 정확히 도착하는 웨이포인트 방식으로 전환. 이론상 맞았지만, 사용자가 테스트하기 전에 GitHub Desktop에서 "Discard all changes"를 눌러버려서 이 시도 자체가 통째로 날아감(그리고 같이 작업 중이던 `CallDirector.cs` 이중 미스 버그 수정도 같이 날아감 — 아래 참고).
3. **최종 방향**: "개미 손들기·클라운 목표 전환은 전부 `CallDirector`의 진짜 리듬 이벤트(`OnCallCue`/`OnPhaseChanged`)에서 직접 트리거하고, 그 사이의 움직이는 방식(스프링/바운스/기울임)만 별도 연출 레이어로 분리"하는 걸로 정리. "언제 바뀌는지"는 이벤트가 100% 결정하고 "어떻게 움직이는지"만 코스메틱하게 처리하니, 나중에 리듬 효과음이 붙어도 자동으로 다 같이 맞음. `clock`/`SongTime` 직접 계산 코드는 다시 걷어냄.

## 인형극(마리오네트) 느낌 연출

클라운이 목표 개미로 딱 붙지 않고 살짝 지나쳤다가 튕기듯 돌아와 자리잡게 하는 **감쇠 스프링**(semi-implicit Euler)으로 이동 구현. 위아래 사인파 바운스 + 이동 속도 기반 기울임(회전)도 추가. 스프링 세기/댐핑/바운스/기울임 전부 인스펙터 노출.

### 개미5→개미1 복귀 시 "개미1을 건너뛰고 개미2로 가는 것처럼 보임" 버그

그룹 사이(리스폰스 이후 다음 그룹 콜까지)에 몇 박 쉬는 구간이 있는데, 클라운 목표는 **실제 다음 그룹의 콜 이벤트가 뜨는 그 순간에만** 바뀌므로, 화면을 가로지르는 복귀 이동이 한 박(0.5초)짜리 좁은 구간에 몰려서 일어남 — 개미1에 채 멈추기도 전에 곧바로 개미2로 목표가 넘어가서 하나의 긴 스윕처럼 보임. 해결: 리스폰스 구간(개미5) 진입 후 `returnToStartDelay`(기본 0.5초)가 지나면, 실제 다음 콜 이벤트를 기다리지 않고 **미리** 목표를 개미1로 돌려놓음. 실제 이벤트가 그보다 먼저 뜨면 자동으로 무시되는 안전한 head-start라 판정/효과음 타이밍엔 영향 없음.

## 판정 이중 카운트 버그 발견 (수정했다가 되돌리기 때 같이 날아감 — 재작업 필요)

"틀릴 때 띡띡 두 번 나면서 두 번 틀리게 된다"는 질문에서 발견: `CallDirector.HandleInput()`이 버튼 입력 시 판정 창 안의 노트만 후보로 찾다 보니, 타이밍이 살짝 빗나가면 "매칭 없음 → 즉시 미스"(스팸 방지용) 등록 + 그 노트는 여전히 안 풀린 채로 남아 나중에 `ResolveTimeouts`가 **또** 미스로 처리 — 미스 하나가 두 번 카운트됨. `HandleInput`의 후보 탐색에서 판정 창 제한을 없애고(살아있는 미판정 노트가 있으면 그 자리에서 바로 Hit/Miss로 확정) 고쳤었는데, **바로 다음에 사용자가 GitHub Desktop에서 전체 변경사항을 되돌리면서 이 수정도 같이 사라짐**. 클라운 이동 관련 작업만 다시 살렸고 이 버그 수정은 재작업 안 함 — 재현 조건과 고치는 방법은 여전히 유효하니 나중에 다시 적용 필요.

## 리소스 교체 → 기획자 A/B 비교를 위해 씬 분리

디자이너가 새 리소스(`광대.png`, `그냥 개미.png`, `잭두 개미 융합.png`, 전부 스프라이트 1장씩)를 넘겨줌. 기존 idle/raised 2프레임 스왑 방식이 불가능해져서, 개미 손들기 연출을 스프라이트 교체 대신 **위로 콩 뛰는 점프**(사인 곡선)로 변경.

적용해보니 기획자가 "이미지 교체 전/후 중 뭘 쓸지 고민된다"고 해서, 씬을 통째로 복제해서 둘 다 바로 Play해볼 수 있게 분리:

- `Stage1_1Scene.unity`: 기존 리소스(Ant.png/개미5.png/Clown_idle.png, 스프라이트 스왑)로 원복. 클라운 이동 타이밍 로직(OnCallCue 직접 연동, returnToStartDelay, 스프링/바운스/기울임)은 그대로 유지 — 이미지만 되돌림.
- `Stage1_1Scene_NewArt.unity` 신규: 새 리소스+점프 연출 버전. `Stage1WaveRideVisuals_NewArt.cs`로 로직을 분리해서 기존 스크립트는 안 건드림. 같은 `Director`/차트를 그대로 참조하니 타이밍은 완전히 동일, 캐릭터 연출만 다름.
- 기획자가 결정하면 안 쓰는 쪽 씬+스크립트는 정리할 예정.

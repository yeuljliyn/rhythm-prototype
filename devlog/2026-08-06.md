# 2026-08-06 개발일지

## Stage1 미니게임 5개, 씬을 나누기로 결정

Stage1이 1-1 파도타기 / 1-2 초단타 / 1-3 존버 / 1-4 물타기(기존 `Stage1Scene`) / 1-5 리믹스 5개 미니게임으로 구성된다는 걸 확인. 각 미니게임이 전용 스프라이트시트·Animator·글루 스크립트를 따로 가지므로 한 씬에 다 몰아넣기보다 **미니게임마다 별도 씬**으로 가기로 함 — `CallPatternData`/`CallClock`/`CallDirector`는 씬 경계와 무관하게 그대로 재사용되니 로직 중복은 없음. 점수는 각 스테이지가 끝날 때마다 그 자리에서 랭크를 보여주는 구조(기획자 확인 완료, 애초에 생각했던 "1-5 끝나야 결과" 안이 아님)라 크로스씬 점수 누적기 같은 것도 당장은 필요 없어짐.

## 1-1 파도타기 첫 구현

개미1~4가 순서대로 손 들어 박자를 보여주고(콜), 개미5(플레이어 담당)가 그 박자에 한 번 응답하는 구조. 기존 `CallEntry.role`(Call/Response)로 표현은 되는데, 콜이 4개인데 리스폰스가 1개인 **비대칭 구조**라 두 가지가 걸림:

- **콜 4개 중 "지금 몇 번째 개미"인지 판별**: `CallDirector.OnCallCue`는 "콜 노트 하나 떴다"는 신호만 주고 어떤 노트인지는 안 알려줌. 대신 콜이 항상 시간순으로만 발생한다는 점을 이용해, `Stage1WaveRideVisuals`가 자체적으로 발생 횟수를 세서 `% 4`로 개미 인덱스(0~3)를 역산하는 방식으로 처리. `CallDirector` 자체는 손 안 댐 — 단, 차트가 "그룹마다 콜 정확히 4개"라는 규칙을 지켜야만 성립하는 구조라 나중에 Call Map Editor로 재편집할 때 주의 필요.
- **Call Map Editor의 Z(에코) 키가 콜 개수를 1:1로 그대로 복제**하는 구조라 "콜4→리스폰스1"을 자동 생성할 방법이 없음. 에디터를 고치는 대신, 이미 있는 기능(직접 노트 배치 + 선택 후 `C`로 role 수동 전환 + 툴바 Group# 수동 증가)만으로 그룹당 5개(콜4+리스폰스1) 수동 배치가 가능하다는 걸 확인 — 코드 변경 없이 해결.

임시 차트(`Stage1_1_WaveRide_Test.asset`, `Stage1_Battle.wav` 재사용, 8그룹 반복)는 스크립트로 생성. 더미 아트(개미 idle/raised 2프레임, 바다+모래 배경)도 처음엔 Unity 에디터 스크립트로 절차적 픽셀아트 생성 — AI 이미지 생성 도구가 없어서 택한 차선책이었는데, 이후 디자이너가 실제 리소스(`Ant.png`, `개미5.png`, `무대배경_전체.png`)를 넘겨줘서 전부 교체함. 개미1~4는 `Ant.png`, 개미5(플레이어용)만 사이보그 컨셉인 `개미5.png`로 따로 구분. 절차생성 더미(`AntSheet.png`, `Beach.png`)는 이제 씬에서 안 쓰는 상태로 남아있음.

## 어제와 같은 Canvas 버그를 오늘 또 만남

`Stage1_1Scene`의 Canvas를 `AddComponent<Canvas>()`로 만들었더니 `renderMode`가 **또** `WorldSpace`로 기본 설정됨 — 어제(2026-08-05) `Stage1DialogueSceneManager` 작업 때 겪었던 것과 똑같은 원인. 에디터 메뉴(`GameObject > UI > Canvas`)로 추가하면 `Reset()`이 호출돼 `ScreenSpaceOverlay`로 잡히는데, MCP 툴로 `AddComponent`만 호출하면 `Reset()`을 안 타서 기본값이 WorldSpace로 남음. 증상도 동일: 카메라가 3D 공간에 떠 있는 UI 평면 일부만 비춰서 "하늘색 배경 조각만 보이고 나머지는 안 보임". **앞으로 MCP로 Canvas를 새로 만들 때는 반드시 `renderMode`를 명시적으로 `ScreenSpaceOverlay`로 지정할 것.**

## Stage1PauseMenuManager 버그 두 개 발견/수정

- **Dim 오버레이가 항상 켜져 있던 버그**: `BuildUI()`에서 반투명 검은 오버레이("Dim")를 `_panel`과 별도 형제 오브젝트로 만들어놓고 `_panel.SetActive(false)`만 호출 — Dim은 꺼주는 코드가 없어서 씬 시작하자마자 화면 전체가 항상 55% 어두워진 상태였음. 확인해보니 **원본 `PauseMenuManager.cs`(BattleScene용)에도 똑같은 버그가 이미 있음** — `Stage1PauseMenuManager`가 그 구조를 그대로 재현한 것. 이번엔 `Stage1PauseMenuManager`만 고치기로 확인받음(원본 BattleScene 파일은 안 건드림).
- **RETRY가 `"Stage1Scene"`을 하드코딩**: 여러 `Stage1_x` 씬이 생기는 지금 구조에서 문제가 되므로 `SceneManager.GetActiveScene().name`으로 교체. `SettingsManager.cs`의 씬 이름 체크(`sceneName == "Stage1Scene"`)도 같은 이유로 `sceneName.StartsWith("Stage1")`로 확장 — 앞으로 나올 1-2~1-5 씬까지 자동으로 커버됨.

## 스크린샷 MCP 툴 관련 삽질

`screenshot-game-view`가 한동안 카메라 배경색만 캡처해서 "Overlay Canvas는 이 툴이 아예 못 찍나" 의심했는데(실제로 CLAUDE.md에 이미 비슷한 경고가 있었음), 알고 보니 진짜 원인은 위의 WorldSpace Canvas 버그였음 — 고치고 나니 스크린샷도 정상. 그 와중에 스크립트 재컴파일 직후 한 번 스크린샷에 완전히 다른 씬(사이버시티 배경)이 잠깐 찍히는 현상도 있었는데, 씬을 `scene-open`으로 다시 로드하니 바로 정상으로 돌아옴 — 저장된 씬 파일 자체는 문제없었고 에디터 세션 캐시성 문제로 추정.

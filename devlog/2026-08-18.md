# 2026-08-18 개발일지

## Call Map Editor "존버 사이클 한번에 찍기" 도구 — 위치 세 번 갈아엎음

지난 세션에 만든 존버 사이클(광대 Tap → 개미 Tap → 플레이어 Hold → 재잠수 Tap) 한번에 찍기 도구의 UI 배치를 이번 세션에서 세 번 옮겼다.

1. **툴바 줄**로 처음 만듦 → "안보여.." — phase 스타일 필드 때와 같은 증상(창을 최대화해도 안 보임, 가로 공간 부족으로 GUILayout이 잘라먹음).
2. **스크롤 캔버스 안, 탐색 박자(파란 마커) 바로 위 인라인**으로 옮김(창 폭 문제는 피함) → "너무... 가려져서 안 보이는데" — 이번엔 다른 증상. 스크롤되는 타임라인 콘텐츠(노트, 그룹 배경 밴드)와 같은 자리를 지나다니면서 시각적으로 묻힘.
3. **스크롤뷰 밖, 타임라인 우상단 고정 오버레이**로 옮김 → 컴파일/데이터는 정상이었지만 "REC/미리듣기/탐색 박자 있는 그 첫 줄에 넣어달라, 다른 줄로 하지 말고"라는 명확한 요청.
4. 최종적으로 **REC/여기서▸/미리듣기/여기서▸/탐색 박자가 있는 툴바 첫 줄 안**, 탐색 박자 필드 바로 뒤에 욱여넣는 걸로 정착. 창 폭이 좁아지면 다시 잘려나갈 수 있는 자리지만, 사용자가 명시적으로 원한 위치라 그대로 둠.

## Stage1-4 신규 미니게임 — 손이 물 붓고(Call) 개미가 따라 붓는(Response) 구조

기획자가 1-4 아트(배경/바닥/손/광대/잭두&개미)를 넘겨줘서 새 미니게임 제작 시작. "손이 물 붓는 걸 먼저 call 하고 플레이어 개미가 물을 따라 response한다"는 기존 `Stage1Scene`(물붓기 MVP)와 비슷한 컨셉이지만 완전히 새 스테이지로 제작.

- `Stage1_4Scene.unity` 신규 생성 — Camera/EventSystem/Canvas/GameManager/SFX/CallClock+CallDirector 공용 뼈대부터 시작해서, 배경/바닥/광대/손/플레이어개미(잭두&개미) 순서로 하나씩 배치.
- 캐릭터 스프라이트는 전부 기획자가 이미 슬라이싱 완료한 상태 — 슬라이싱 자체는 절대 안 건드리고, 각 프레임이 정확히 어떤 상태(평상시/붓는 중/실패/성공)인지는 슬라이스 이름 순서만 믿지 않고 실제 PNG를 열어서 그림 내용으로 확인 후 매핑(잭두&개미 쪽은 `_0/_1/_4`처럼 번호가 안 이어져 있어서 특히 주의).
- **Canvas가 기본값 World Space로 생성되는 버그**: `Canvas` 컴포넌트를 스크립트로 직접 `AddComponent`하면 유니티가 Screen Space - Overlay가 아니라 World Space로 잡는다(에디터 메뉴 UI>Canvas로 만들 때만 자동으로 Overlay가 됨). 그 상태에선 카메라가 그 위치를 비추지 않아서 배경도 캐릭터도 전부 화면에 아예 안 보였음 — "아무것도 안보이는데"로 리포트받고 원인 파악, `renderMode`를 명시적으로 `ScreenSpaceOverlay`로 고쳐서 해결.
- **헤드리스 세션에서 방금 생성한 UI 오브젝트가 스크린샷에 안 잡히는 현상**: 데이터(포지션/스프라이트/색/활성 상태)는 전부 정상인데 새로 만든 오브젝트만 계속 안 보여서, 이미 렌더링되고 있던 기존 오브젝트(광대)에 같은 스프라이트를 임시로 얹어 테스트해보니 거기선 바로 나옴 — 스프라이트 문제가 아니라 이 환경에서 막 생성된 UI가 캔버스 렌더 등록이 한 박자 늦게 걸리는 것으로 추정(전에 겪은 "에디터 포커스 없으면 프레임이 이상하게 돈다"는 문제와 같은 계열). 실제 씬 데이터는 정상이라 에디터에서 직접 보면 바로 보임 — 이후 확인됨.
- `Stage1AntPourVisuals.cs` 신규 작성 — `CallDirector`의 `OnCallCueGroup`(손이 콜 낼 때 → 손 붓는 포즈로 펄스), `OnGroupJudged`(플레이어 응답 판정 → Hit면 개미 붓는 포즈+광대 성공 표정, Miss면 개미 실패 포즈+광대 실패 표정)만 구독하는 순수 스프라이트 교체 방식(Animator 없음, Stage1SurviveVisuals와 같은 스타일). CallDirector는 여전히 Hand/PlayerAnt/Clown을 전혀 모름.
- "판정 구간 아닐 때 탭해도 개미가 물붓는 움직임은 하게 해달라(판정은 안 되고)" 요청으로 `OnResponsePress`(판정 여부 무관하게 매 입력마다 발화)도 구독 추가. 처음엔 취소-후-재생 방식으로 짰다가 "연타하면 개미가 계속 붓는 상태로 고정되지, 원상복귀 후 다시 바뀌는 게 아니다"는 버그 리포트 — `OnResponsePress`는 마구 누르기 쿨다운 중에도 무조건 발화하는데 취소-후-재생이다 보니 원상복귀할 틈도 없이 계속 리셋되고 있었던 것. 이미 펄스 재생 중이면 새 트리거를 무시하는 busy-guard 방식(8/11에 다른 미니게임들에서 정착시킨 것과 같은 패턴)으로 교체해서 해결. 단, 실제 판정(`OnGroupJudged`)은 여전히 취소-후-재생이라 Miss가 뜨면 항상 우선권을 가짐.
- 테스트용 `Stage1_4_Test.asset` 채보 신규 작성(콜→1박 뒤 리스폰스 페어 8세트, 4박 간격). 배경음악은 마침 이름이 맞는 `Drowned_Clown_Drip_Drop.wav`로 임시 배정. 마구 누르기 쿨다운은 컨셉이 같은 1-1 기준(0.5초)으로 맞춤(처음에 0.3으로 찍어놨다가 "다른 스테이지에 있잖아"라는 지적으로 정정).

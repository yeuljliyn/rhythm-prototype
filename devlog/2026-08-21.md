# 2026-08-21 개발일지

## Call Map Editor — 페이즈를 인트로 구간으로 못 끌어오던 버그

"인트로 구간에는 페이즈 못찍게 되있어 M1부터 찍혀"라는 리포트. `CommitPhaseDrag`와 라이브 드래그 프리뷰가 `startBeat`/`endBeat`를 `Mathf.Max(0f, ...)`로 강제 클램프하고 있어서, 페이즈를 만든 뒤 시작점을 인트로 구간(박자 0 이전)으로 끌어당기거나 페이즈 전체를 왼쪽으로 옮기면 항상 박자 0(M1)으로 튕겨 돌아갔음. 클릭으로 새 페이즈를 만드는 경로는 원래부터 음수 박자를 허용했으므로, 드래그 쪽에만 있던 불필요한 하한선 3곳을 제거.

## StartScene 스프라이트 흰 박스 + UI 에디터 오브젝트 전환

"startscene갑자기 리소스들이 하얀색으로 보이는데 뭐지" 리포트로 원인 파악: 8/13 리소스 폴더 재정리(시작/, 로비/, 1/ 하위 폴더로 이동) 이후 `StartSceneManager`의 `Resources.Load` 호출 3곳이 옛 경로(하위 폴더 없이 파일명만)를 그대로 쓰고 있어서 배경/로고/버튼 4개가 전부 null 스프라이트로 떨어져 흰 박스로 보이던 것 — `"시작/"` 프리픽스 추가로 해결.

이어서 "startscene 플레이해야 보이는데 scene뷰에서도 보이게해서 내가 직접 오브젝트들 움직이고 수정할 수 있게 끔 해줄래" 요청으로, `Start()`에서 코드로 절차적 생성(`BuildUI()`/`CreateButton()`)하던 방식을 에디터에 직접 배치된 영구 GameObject(Canvas/Background/Logo/버튼 4개/EventSystem)로 전환 — Play 없이 Scene 뷰에서 바로 보고 옮길 수 있음. 버튼 `OnClick()`은 정적 `SFXManager.PlayClick` + 인스턴스 로직 호출을 Persistent Listener로 연결해서 스크립트 재컴파일 후에도 유지되게 함.

부수적으로, 이번 세션에서 Play 테스트하며 화살표(←/→) 글리프가 `LiberationSans SDF - Fallback.asset`의 동적 아틀라스에 캐싱됨(TMP가 자동으로 만드는 파일이라 별도 처리 없이 커밋에 포함).

## Stage1-5(리믹스) 스테이지 뼈대

`Stage1_5Scene` 하나에 1-1/1-2/1-3/1-4 화면(`Screen_1_1`~`Screen_1_4`, 각 스테이지의 비주얼/글루 스크립트를 원본 씬에서 그대로 복제)을 전부 배치하고, `CallPatternData.phases`(박자 구간별 `styleId` 라벨)를 기준으로 매 프레임 현재 페이즈에 맞는 화면만 `SetActive`로 켜는 `Stage1RemixPhaseSwitcher` 신규 작성. 전환은 페이드 없이 즉시(SetActive 토글) — 비활성화된 화면의 Visuals 스크립트는 자기 `OnDisable()`로 `CallDirector` 구독을 스스로 끊으므로, 4개 미니게임이 하나의 `CallDirector`를 공유해도 서로 간섭하지 않음.

페이즈 순서는 기획자가 나중에 Call Map Editor에서 직접 찍을 예정이라 아직 미정 — 이번엔 어떤 순서가 오든 동작하는 인프라만 구성. `Stage1_5_Remix.asset`은 테스트용으로 임의 생성한 6구간 페이즈 + 각 스타일에 맞는 콜/리스폰스 샘플 채보(실제 음악 미배정).

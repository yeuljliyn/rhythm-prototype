## Stage1-1 인라인 튜토리얼(연습) 시스템

리듬천국 스타일 콜-리스폰스 연습 파트를 처음으로 구현. 핵심 설계: 한 사이클짜리 `CallPatternData`(`loopLengthBeats > 0`)를 매끄러운 무한 반복(오디오 팝 없음)으로 재생하며, 시범 1회(입력 무시) 후 3번 성공할 때까지 따라하기, E키 2초 홀드로 언제든 스킵.

- `CallDirector`에 `AppendCalls`/`ReplaceCalls` 추가, `CallEntry.forceDemo`(NonSerialized, 런타임 전용)로 "판정 없이 보여주기만" 구분 — `role`은 그대로 유지해서 응답 캐릭터 전환(`OnPhaseChanged`)은 정상 동작하게 함.
- `PracticeLoopExtender` 신규: 한 사이클을 시범 사본(rep 0) + 반복 판정 사본(rep 1..N)으로 이어붙여 재생, `refillThresholdCycles` 기준으로 계속 앞서 버퍼링.
- `Stage1PracticeGate` 신규: 세그먼트 순차 진행, 말풍선 대사 게이팅(스페이스/클릭으로 확인해야 다음으로), 스킵/카운터 UI, 본편 전환 시 `GameManager.ResetGame()`으로 연습 판정 초기화.
- `Stage1SpeechBubble`/`Stage1SkipHold`/`Stage1PracticeCounter` 신규: 절차적 생성 대신 씬에 미리 배치된 오브젝트를 참조하는 방식 — Play 없이 에디터에서 위치 조정 가능. 말풍선은 `Awake` 시점에 에디터에서 배치해둔 위치를 오프셋으로 자동 캡처해서, 옮긴 위치가 Play 중에도 그대로 유지되게 함("말풍선 위치 조정하고싶은데... play를 눌러야 생성되네" 리포트로 대응).
- `Stage1TitleCard` 신규: 스테이지 인트로씬 공용 — 타이틀 텍스트 5초 표시 후 `SceneTransitionManager`로 페이드 전환.
- `Stage1_1_Practice.asset`: 연습용 placeholder 차트(BPM 122, 실제 리듬은 기획자가 나중에 Call Map Editor로 재작업 가능).

## Stage1-1 인트로씬 + 씬 전환 인프라 버그 2건

`Stage1_1IntroScene` 신규: 5초 타이틀 카드, 본편(`Stage1_1Scene`)과 동일한 Background/Sea 오브젝트를 같은 위치로 재사용해 페이드 전환이 끊김 없이 이어지도록 함. 이어서 "파도 위에 빈 양동이가 왼쪽에서 오른쪽으로 출렁출렁 흘러가고, 개미들이 뒷모습으로 그걸 보고 있는" 연출을 `Stage1IntroBucketDrift` + 개별 배치 캐릭터(잭두/개미2)로 구현. 배치는 4개 리소스(양동이/개미/잭두/타이틀)가 전부 같은 2048×1143 "원본 합성 프레임"에서 잘려나온 걸 이용해서, 각 스프라이트의 crop 좌표를 그대로 1920×1080 캔버스 좌표로 비례 변환하는 방식으로 처리 — 잭두가 정중앙이라는 원래 구도가 그대로 유지됨.

전환 테스트 중 실제로 겪은 인프라 버그 2건도 함께 수정:
- `Stage1TitleCard`: 이전 플레이 세션에서 `Time.timeScale`이 0으로 남아있으면 `WaitForSeconds` 코루틴이 영원히 안 끝나는 문제(`CallClock.Awake()`의 기존 방어 로직과 동일 원인) — `Awake`에서 `timeScale=1` 리셋 추가.
- Build Settings에 `Stage1_1~1_5Scene`, `Stage1DialogueScene`이 전혀 등록되어 있지 않아 `SceneManager.LoadScene(이름)`이 항상 실패하던 문제 — 지금까지 에디터에서 씬을 직접 열어 테스트해와서 안 드러났었음. 전부 등록.
- 그 밖에 Stage1_1IntroScene 자체에 Camera/AudioListener가 없어서 "No cameras rendering" 경고가 뜨던 것도 본편과 동일한 카메라 설정을 추가해 해결.

이후 사용자 피드백으로 양동이 높이(284→167→53)와 좌우 이동 범위·속도를 여러 차례 재조정(처음엔 화면 밖까지 갔다 오게 했더니 "너무 빠르게 지나감" 피드백으로 시작 위치를 화면 안쪽으로 당기고 이동 거리를 줄임), 사용자가 추가한 `Sand` 오브젝트를 Background 앞/Sea보다 앞쪽으로 레이어 정렬.

## Stage1-2(초단타) 컵 풀 6→8 확장

"1-2스테이지에 스폰되는 Cup 갯수가 총 6개뿐이라 동시에 7개 필요한 상황에서 버그가 생긴다"는 문의로 원인 파악: `FindFreeCupSlot`이 8개 슬롯이 전부 사용 중이면 무조건 slot 0을 강제로 재활용해서, 그 순간 slot 0을 쓰던 다른 그룹의 컵이 비행 중 엉뚱한 곳으로 튕기는 버그였음. `cupPool`을 6→8로 확장(이 컴포넌트를 쓰는 `Stage1_2Scene`/`Stage1_5Scene` 둘 다 컵 오브젝트 2개씩 추가하고 배열에 연결)해서 실사용 최대 동시 개수보다 여유 있게 잡아 충돌 자체를 없앰.

## Stage1-2/1-3/1-4 튜토리얼(연습) + 인트로씬 4개 (1-1 패턴 복제)

1-1에서 검증된 연습 시스템(`PracticeLoopExtender`/`Stage1PracticeGate`/말풍선·스킵·카운터 UI)을 나머지 세 스테이지에 그대로 복제. 대사는 기획서 원문 그대로("목이 마르신 모양입니다..." / "누가 위에서 퍼붓습니다..." / "저쪽이 먼저 붓습니다..." 등, 패턴 전환 시점 대사 포함).

각 스테이지의 실제 판정 구조를 그대로 반영한 연습 차트를 새로 설계(둘 다 A/B 두 패턴, BPM 122 placeholder):
- **1-2(초단타)**: 개미 5마리 릴레이(Call) + 플레이어(Response) — A는 0.5박 균등 간격, B는 엇박(0.375박 섞임).
- **1-3(존버)**: 광대 Tap Call → 개미 Tap Call → 플레이어 Hold Response → 재잠수 Tap Call 4entry/사이클(`Stage1SurviveVisuals` 문서에 적힌 실제 구조 그대로) — A는 "하나·둘·셋 순서대로"(beat 1/2/release 3), B는 "셋이 동시에"(전부 beat 2).
- **1-4(물타기)**: 손(Call) → 플레이어(Response) 1쌍 — A/B는 콜-리스폰스 간격만 다르게.

인트로씬(`Stage1_2IntroScene`~`Stage1_5IntroScene`)도 1-1과 같은 구조(`Stage1TitleCard`, 5초 후 페이드)로 4개 신규 생성. 1-2/1-3/1-4는 본편 Background를 그대로 재사용, 1-5는 리믹스라 특정 스테이지 배경 하나로 대표하기 애매해서 단색 배경으로 대체 — 1-5는 연습이 없으므로 인트로가 곧장 본편으로 연결됨. Build Settings에 4개 씬 전부 등록.

## CallDirector 버그 2건 — 연습(practice) 중 컵이 중간에 멈추는 문제

1-2 연습을 실제로 플레이해보며 발견된 버그 2건, 둘 다 `Stage1QuickTapVisuals`의 컵 릴레이 마지막 구간이 `CallDirector.OnGroupJudged`에만 의존한다는 점이 원인.

1. **"해보십시오" 뜨기 전 시범(데모) 중 컵이 개미4에서 멈춤**: `ResolveTimeouts`가 데모(`forceDemo`) 노트는 시간이 지나면 그냥 정리만 하고 `OnGroupJudged`를 전혀 안 쏘고 있었음 — 데모의 Response 노트는 원래 판정 대상이 아니라서 `Resolve()`를 거치지 않기 때문. 데모 Response 노트가 자연스럽게 끝나는 순간 `OnGroupJudged(groupId, Hit)`만 별도로 쏘도록 수정(`Resolve()`를 안 거치므로 점수엔 영향 없음). 다른 두 구독자(`Stage1SurviveVisuals`는 Hit 시 아무 것도 안 함, `Stage1AntPourVisuals`는 성공 리액션+풍선)도 안전한지 확인 후 적용.
2. **A 패턴 3번 다 맞췄는데 컵이 한 번 더 나와서 B 시작하며 멈춤**: 콜이 겹쳐도 되는 설계상, 3번째 Hit이 뜨는 순간 다음 사이클의 릴레이가 이미 개미들 사이를 날아가고 있는 경우가 흔함. 지금까지는 3번 다 맞추면 오디오 페이드(1초)가 끝난 뒤에야 세그먼트를 통째로 꺼버려서, 그 사이 날아가던 컵이 마지막 판정을 영영 못 받고 멈춰있었음. `CallDirector.ForceResolvePending()` 신규 추가(아직 안 끝난 라이브 판정을 전부 즉시 Hit으로 마무리, 데모는 제외) — `Stage1PracticeGate`가 3번 성공(또는 스킵) 즉시 페이드 시작 전에 이걸 호출하고 해당 세그먼트의 `CallDirector`를 바로 비활성화하도록 수정, 새 릴레이는 더 이상 안 뜨고 이미 날아가던 컵은 즉시 완주하게 됨.
